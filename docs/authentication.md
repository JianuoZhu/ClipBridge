# PIN 与管理员登录

ClipBridge 使用两种入口：共享剪贴板输入 PIN 即可使用；长期文件库必须通过独立管理员账号登录。

| 能力 | PIN 会话 | 管理员会话 |
| --- | --- | --- |
| 发送、读取、复制和删除传输文字 | 支持 | 支持 |
| 上传、下载和删除传输文件 | 支持 | 支持 |
| 文件库列表、搜索、下载、预览 | 禁止 | 支持 |
| 文件库上传、重命名、文本编辑、删除 | 禁止 | 支持 |

这些权限由服务端根据会话角色检查，包括直接访问文件 URL。所有传输内容仍是共享空间，没有多个独立用户账号或设备私有空间。

## 配置

```dotenv
CLIP_PIN=1223
CLIP_USERNAME=admin
CLIP_PASSWORD=
CLIP_SESSION_DAYS=30
```

`CLIP_PIN` 默认为 `1223`，接受 4–12 位数字，前导零会保留。管理员沿用原来的 `CLIP_USERNAME` 和 `CLIP_PASSWORD`。要使用文件库，设置 12–1024 个字符的管理员密码；留空会关闭管理员登录，但不影响 PIN 使用。PIN 不授予文件库权限。

默认 PIN 是公开示例值，部署时应改为自己的 PIN；短数字 PIN 的保护强度低于随机密码。PIN 与管理员密码只配置在服务端，不下发到网页。HTTPS 保护浏览器连接，WireGuard 保护节点间隧道。

## 会话流程

1. 浏览器先请求 `GET /api/session`，已有有效会话即可继续使用。
2. 普通登录向 `POST /api/auth/login` 提交 JSON `{ "pin": "1223" }`；管理员向 `POST /api/auth/admin` 提交用户名和密码。
3. 服务端检查同源写入标记、Origin、限速和凭据。两类凭据均经 scrypt 派生并以恒定时间比较。
4. 成功后生成随机令牌，数据库仅保存令牌摘要和角色，通过 `HttpOnly`、`SameSite=Strict` Cookie 保持会话。生产环境还使用 `Secure` 和 `__Host-` 前缀。
5. 每次 API 请求重新验证会话。文件库请求额外验证 `admin` 角色；长时间上传或编辑在提交前再次检查。
6. 管理员升级登录会替换当前 Cookie 并撤销原会话。文件库变更事件仅发送给管理员，传输事件发送给所有有效会话。

按应用看到的连接 IP 和登录入口分别限速：15 分钟内最多 5 次未成功尝试，成功后清除该入口计数，同时最多进行 4 次验证。代理部署可能让设备共用同一个连接 IP；限速计数保存在进程内。

## 重启、升级和退出

会话默认固定有效 30 天，不随使用自动续期。凭据不变的重启保留会话。首次升级到 PIN/角色版本，或修改 PIN、管理员用户名、管理员密码后重启，会撤销全部旧会话，保留传输数据和文件库。

直接运行时重启 `npm start`；Docker 部署使用 `docker compose up -d --build` 重新创建容器。修改 `CLIP_SESSION_DAYS` 仅影响新会话。

点击“退出”撤销当前会话并清空页面中的列表、预览和编辑内容。共享该 Cookie 的页面一同退出，其他独立会话不受影响。没有注册、找回密码或单设备撤销管理页面；部署者可通过修改配置并重启撤销全部会话。
